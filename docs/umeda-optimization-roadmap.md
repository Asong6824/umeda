## 代码驱动的外观方案（2026-11-23，首批实施）

最终风格与界面形象尚未确定，先提供可替换的外观架构，再按主人的要求逐步修改代码尝试。
主人明确不需要新增前端切换功能：不增加方案设置、预览／应用控件或持久化偏好。
外观与 KOS／Agent 业务分离，复用现有主题、组件和语义 Token，不另建主题引擎。

- **首批**：代码中保留当前形象，增加简洁形象；桌面与手机共用一个当前方案常量，
  通过修改代码、重新构建／加载来应用。资源按语义入口集中，分别适配平台素材；
  不改变原有浅色／深色／跟随系统以及配色／字体／壁纸设置，不改写用户定制。
- **配置化已接入**：统一入口为 `packages/design-tokens/src/umeda-appearance.json`。
  当前方案、两端浅深色配色、桌面字体栈／默认字号与基础变量、手机字体／字号／行高／
  圆角／间距／动效时长通过现有 Terrazzo 流程生成共享配置，再进入平台原有主题与 Token。
  修改配置、生成并重启／构建即可应用，已有字段不需逐页改代码；默认仍为 `original`。
  本地主题与字体显式覆盖优先，旧 Cindy 数值与冻结快照保留；手机嵌套代码字体继续继承。
- **逐步扩展**：形象资源覆盖标志、头像、首页插画与应用内启动画面；视觉风格通过
  现有主题与 Token 演进，首页／导航等布局仅在实际尝试需要时增加明确变体。
  自定义伙伴头像和用户选定的壁纸不因方案切换被改写。
- **兼容身份**：产品名为 Umeda；方案只改变呈现，不改变包 ID、数据目录、凭证、
  协议、后端或业务归属。系统图标、原生启动图、小组件及系统权限文案另行适配与打包，
  不承诺随应用内方案即时切换。
- **验收**：两种方案各自覆盖浅色／深色；改变代码中的当前方案后，两端消费同一选择；
  已有本地主题与素材回退继续工作。无 Xcode 时先做共享逻辑、桌面界面和
  手机 JS 层，iOS 编译、安装及真机启动效果留待后续集中验证，分别记录缺口。

首批接入桌面新建页品牌区、加载标志、分享页脚及手机应用内启动占位。
当前方案仍为原有形象，简洁方案为文字标志并省略相应角色图；普通头像、登录页、
原生启动图和系统图标仍待后续逐项接入，不表示全应用资源和布局已完成替换。
代码入口、扩展方法及验证边界见[外观架构](dev-rules/umeda-appearance.md)。

没有 Xcode 的开发机可先完成设计、共享逻辑、桌面页面和自动验证。类型检查、定向测试、

## Umeda 组合宿主与 KOS 知识库定位（2026-11-22，历史范围）

本节保留当时迁移分工；KOS 的整体范围已由本页开头 2026-11-23 的底层融合方向扩展，
不再将下文「仅知识库」作为未来设计的范围上限。业务唯一写入和旧数据保留要求继续适用。

旧 KOS 的目标、项目、行动事项、排期与业务进度上移为跨设备／Agent 的 Umeda 应用能力。
Umeda 是总入口和组合宿主；KOS 是其内供 Agent 读写的知识库，存放材料、摘录、研究产物、
知识／方法、来源与证据。理解、研究、整理和写入由接入的 Agent 完成，Umeda 提供存取、
展示、同步与执行设施，不恢复旧 DSH-KOS 专属 Agent 或独立知识业务系统。工作对象引用
知识内容，不再维护两套项目状态；当前 0.4.0 的旧解析器与界面仍保留。

U21 先形成字段／关系映射、唯一写入归属和合成迁移验收，作为完整工作管理上线的前提；
单机 Session 换引擎的最小验证可继续先行。业务行动与执行 Session 分开：行动可以由人
完成或关联多条执行，Session 仍复用现有运行时，不新建第二个 Agent loop。不是直接删掉
Vault 的 Goal／Project／Task 文档，也不是把旧 Task 全部转换为 Session。

## 已具备的基础

- Mac 使用 Electron，手机使用 Expo / React Native；KOS React Web 前端在两端嵌入，
  已有看板、记录、Markdown 编辑、属性、PDF／EPUB 阅读、批注与阅读位置。
- Mac 独立同步本地目录；Worker + DO + R2 保存文件和版本，手机直接读取云端副本。
  已有条件写、哈希校验、冲突副本、被替换版本保留、持久编辑队列及阅读记录合并。
- 已做索引批量、空增量避免全量重写、变更提示、本地文件监听、失败退避。
  两轮同库交替只读测试平均索引耗时约 11.7 秒降至 5.0 秒，8 请求变 1 请求；
  此数值含公网线路波动，不是所有内容首屏或同步延迟的指标。
- 指令有独立的云端持久收件箱与电脑接收回执。手机关闭代理后，目录、正文、返回以及
  驱动 Mac Agent 收到预期回复已由用户实机确认；未据此验证全部网络与后台场景。

## 需要先复现的候选

- **初始化时序**：Store 的 `namespace` 初始为空，`preference()`／`savePreference()` 不等待
  `info` 就绪；App 的 initialize 与偏好 effect 分别启动。代码存在时序窗口，应使用延迟
  `info` 的生产入口夹具确认早期读写是否落在错误 key，再决定修复。尚未确认用户数据损失。
- **大型资料性能**：看板有多次对象过滤和解析，目录已有 60 项分页；在千／万文档、长文、
  大量批注样本上测量后再决定增量计算、后台索引和虚拟列表，不凭组件代码长度判断瓶颈。
- **云端长期保留**：[Vault 服务](../packages/device-link-relay/cloudflare/vault.ts) 有不可变 blob、
  历史元数据与删除记录，但还没有完整的回收产品及演练。先量化失败暂存、历史引用和容量，
  制定 tombstone／恢复保留窗口后设计回收，不能直接上线定时删除。
